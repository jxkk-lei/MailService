# MailService

MailService — учебный сервис пользовательских рассылок. Консольная версия создаёт пользователей, рассылки, подписки и сообщения, а веб-интерфейс Django позволяет просматривать эти данные и переходить между связанными объектами.

## Возможности веб-интерфейса после ПР6

- Главная страница с описанием сервиса и количеством пользователей, рассылок, сообщений и подписок.
- Карточки рассылок с владельцем, количеством читателей и сообщений, статусом наличия подписчиков.
- Подробная страница рассылки с её подписчиками и сообщениями.
- Список пользователей и профиль пользователя с собственными рассылками и подписками.
- Список сообщений с сокращённым текстом и подробная страница с полным текстом.
- Список подписок со ссылками на пользователя и рассылку.
- Понятные сообщения при пустых коллекциях и отсутствующих объектах с HTTP 404.
- Единая навигация, адаптивное оформление, локальные CSS, SVG-логотип и JavaScript.

Добавление данных выполняется через консольную версию. Веб-часть на этапе ПР6 предназначена для просмотра. Создание сообщения моделирует рассылку внутри проекта; подключение почтового сервера не реализовано.

## Технологии и архитектура

Python, Django 5.2, JSON, Bootstrap 5.3.3, pytest, pytest-django, flake8.

```text
URL → view → JSON / JsonStorage → объекты предметной области
          → context → Django-шаблон → HTML-ответ
```

Модели `User`, `MailingList`, `Subscription`, `Message` и бизнес-логика `MailService` сохранены. `web_data.load_service()` использует существующий `JsonStorage` из ПР3. Страницы читают `data/mailservice.json`; GET-запросы не изменяют данные. Отсутствующий файл даёт пустые коллекции, ошибки чтения и структуры JSON регистрируются в журнале. Данные предметной области по-прежнему хранятся в JSON. SQLite используется только стандартными Django-приложениями, например администратора и сессий.

HTML находится в шаблонах. Представления загружают объекты, выбирают связанные данные, готовят контекст и вызывают `render()`. Отдельной функции `page()` нет. Преобразование строковой даты сообщения в объект `date` для отображения выполняется в `web_data.message_rows()`; сохранённый формат даты не меняется.

## Структура

```text
MailService/
├── data/mailservice.json
├── models/                         # User, MailingList, Message, Subscription
├── services/mailing_service.py     # Бизнес-логика
├── storage/json_storage.py         # JSON-хранилище
├── main.py                         # Консольный интерфейс
├── manage.py
├── mailservice_web/                # Настройки и общие маршруты Django
├── templates/
│   ├── base.html                   # Общий каркас, CSS, JS, подвал
│   ├── 404.html                    # Неизвестный URL при DEBUG=False
│   └── includes/navigation.html
├── homepage/
│   ├── templates/homepage/index.html
│   ├── static/homepage/
│   │   ├── css/style.css
│   │   ├── img/logo.svg
│   │   ├── js/main.js
│   │   └── vendor/                 # Bootstrap и его лицензия MIT
│   ├── tests.py                    # 21 тест веб-интерфейса
│   ├── urls.py
│   └── views.py
├── users_web/templates/users_web/  # list.html, detail.html
├── mailing_lists_web/templates/mailing_lists_web/
│   ├── list.html
│   ├── detail.html
│   └── includes/                  # card.html, status.html
├── messages_web/templates/messages_web/  # list.html, detail.html
├── subscriptions_web/templates/subscriptions_web/list.html
├── tests/test_mailing_service.py   # 6 тестов предметной области
├── reports/                       # Отчёт ПР6 и снимки приложения
├── web_data.py
├── pytest.ini
└── requirements.txt
```

`TEMPLATES[0]["DIRS"]` указывает на корневой `templates/`, а `APP_DIRS=True` включает поиск в приложениях. Имена каталогов приложений в путях шаблонов предотвращают конфликты. Все страницы наследуют `base.html` через `{% extends %}` и переопределяют блоки `title` и `content`. Навигация, карточка рассылки и статус подключаются через `{% include %}`; карточка получает явно заданные переменные с `with ... only`.

В шаблонах используются:

- `{% for %}` и `{% empty %}` — коллекции и сообщения при отсутствии элементов;
- `{% if %}` / `{% else %}` — статус подписчиков и отсутствующие объекты;
- `{% url %}` — все внутренние переходы; пространства имён заданы через `app_name`;
- `length`, `default`, `date`, `truncatechars`, `first`, `upper` — количество, значения по умолчанию, даты, предпросмотр текста и аватары;
- `{% load static %}` и `{% static %}` — CSS, SVG и JavaScript.

Собственный CSS оформляет шапку, карточки, таблицы, статусы и мобильную версию. JavaScript устанавливает текущий год в подвале. Все ресурсы, включая Bootstrap, находятся в проекте: интернет для оформления не нужен. Автоматическое экранирование Django включено; текст сообщений выводится как текст.

## Установка и запуск

Из корня проекта:

```bash
python3 -m venv venv
source venv/bin/activate
python -m pip install -r requirements.txt
python manage.py check
python manage.py migrate
python manage.py runserver
```

Для Windows вместо команды активации используется `venv\Scripts\activate`.

Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/).

| Адрес | Именованный маршрут | Назначение |
|---|---|---|
| `/` | `homepage:index` | Главная и статистика |
| `/users/` | `users:list` | Пользователи |
| `/users/<id>/` | `users:detail` | Профиль пользователя |
| `/lists/` | `mailing_lists:list` | Карточки рассылок |
| `/lists/<id>/` | `mailing_lists:detail` | Рассылка, подписчики и сообщения |
| `/messages/` | `messages:list` | Сообщения |
| `/messages/<id>/` | `messages:detail` | Полный текст сообщения |
| `/subscriptions/` | `subscriptions:list` | Подписки |

`<id>` — целочисленный идентификатор из JSON. В текущих данных доступны `/users/1/`, `/lists/1/`, `/messages/1/`. Данные для демонстрации можно создавать в консольном интерфейсе:

```bash
python main.py
```

### Обработка 404

Представление подробной страницы ищет объект. Если его нет, передаёт `None` в тот же шаблон и вызывает `render(..., status=404)`. Шаблон выбирает сообщение через `{% if %}` / `{% else %}`. Например, `/lists/999999/` возвращает оформленную страницу «Рассылка не найдена».

Для неизвестного маршрута задан `handler404 = "homepage.views.not_found"` и общий шаблон `404.html`. Django использует этот обработчик при `DEBUG=False`. При включённом `DEBUG` для неизвестного URL отображается стандартная диагностическая страница Django. Это не меняет обработку отсутствующих объектов в подробных страницах.

## Проверки

```bash
python manage.py check
python -m pytest -v
python -m flake8 . --extend-exclude=venv
```

Результат ПР6: **27 тестов проходят**, Django не обнаруживает ошибок конфигурации, flake8 завершается без замечаний. Веб-тесты используют временный JSON и не изменяют `data/mailservice.json`. Они проверяют страницы, связи объектов, шаблоны и include, именованные URL, пустые коллекции, фильтры, 404, экранирование HTML, неизменность данных при GET и доступность статики. Исходные 6 тестов предметной области сохранены.

Дополнительно веб-тесты можно выполнить стандартным Django runner:

```bash
python manage.py test homepage
```

Проверка в Chrome охватывает 8 основных страниц, страницу отсутствующей рассылки, внутренние ссылки, загрузку ресурсов и выполнение JavaScript. Ширины экрана: 320, 390, 768 и 1440 px. Результаты сохранены в `reports/browser_verification.json`, снимки — в `reports/screenshots/`.
